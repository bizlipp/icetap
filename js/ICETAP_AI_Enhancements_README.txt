# ICETAP AI Enhancements – Phrase & Timing Intelligence

This README documents new features added to `ai.js` and `sitestatus.js` as of May 2025, expanding the ICETAP platform's insight and coaching capabilities.

---

## ✅ New Features in `ai.js`

### 1. 🔁 markRepeatCalls(calls)
- Flags `call.repeat = true` if the same customerId has multiple calls within a defined window (default 72 hours).
- Enables repeat contact tracking, missed opportunity detection, and follow-up chains.

### 2. 🧠 extractFrequentPhrasesBySpeaker(calls)
- Scans transcripts across all calls.
- Separates and counts frequent **bigrams** (2-word phrases) by speaker (`agent` vs `customer`).
- Returns top 10 phrases for each group with counts.
- Used to detect trends in language such as:
  - Customer confusion (“i already called”)
  - Agent rapport (“let me check”, “i understand”)

### 3. ⏱ analyzeTranscriptGaps(call)
- Analyzes gaps between transcript lines using `start` and `end` timestamps.
- Flags:
  - **Dead air instances** (>10 seconds of silence)
  - **Delayed agent replies** (>7 seconds after customer speaks)
  - **Longest silent gap** in the call
- Used to flag timing risks and responsiveness issues.

## 🖼️ New Features in `sitestatus.js`

### 4. 🧠 renderPhraseInsightBlock(calls)
- Displays two side-by-side lists:
  - Top Customer Phrases
  - Top Agent Phrases
- Provides context-based coaching insights and highlights communication trends.
- Uses a visually styled block within SiteStatus reports.

### 5. 🕒 renderTimingInsightBlock(calls)
- Summarizes timing behavior across the filtered call set:
  - Total dead air instances
  - Delayed agent responses
  - Longest silence recorded
- Automatically included in SiteStatus view when transcripts are available.

### 6. 🔗 Integrated Into renderSiteStatusReport()
- Both blocks are appended at the bottom of the Site Status summary report.
- These features work seamlessly with filtering and exported call sets.

---

## 📌 Requirements

- `call.transcript[]` must include:
  - `speaker`
  - `text`
  - `start` and `end` (in seconds or hh:mm:ss)
- `call.customerId` should be pre-normalized from `meta["Customer phone number / email address"]`
